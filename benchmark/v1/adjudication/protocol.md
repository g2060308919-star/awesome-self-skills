# V1 Expert Adjudication and Capture Protocol

This protocol keeps generation inputs, captured outputs, and hidden labels in separate directories. The current repository contains only a synthetic pilot used to test machinery. It is not external expert evidence and is never release-eligible.

## Frozen capture procedure

For every PRD, run exactly `long-prompt`, `test-case-designer`, `technique-router`, and `generate-test-cases` three independent times against the same original `sources/` and `task.json`. Do not expose expert obligations, supported-assertion decisions, accepted-case decisions, historical-defect labels, prior outputs, or diagnostics to a generation session. Store raw outputs under the case's `captured/` directory, never below its label directory.

Every capture records the Skill, compiler, Schema, model, prompt/reference, baseline, benchmark version, repeat number, source digest, task digest, capture kind, and review time. The manifest freezes the first seven provenance fields separately for each system; every repeat must match that identity exactly. The source and task digests bind every run to the exact original materials and task scope. A separate path-independent content digest prevents identical PRD bytes from becoming multiple corpus items merely by renaming files.

The closed capture summary may contain only the frozen metric arrays and four process observations. Each capture references its own distinct original, opaque raw artifact by a safe relative path beneath the isolated `captured/` root and records the SHA-256 digest of its exact bytes. A second, independently digest-bound extraction record identifies the capture, raw digest, reviewer, review time, offline extraction method, and derived score summary. The loader verifies both exact-byte digests and the extraction-to-summary binding. All per-case label roots and capture roots are pairwise disjoint, and raw/extraction artifacts have globally unique resolved physical paths. The loader rejects shared paths, hardlinks, symlinks (including the benchmark root itself), ancestor escape, root overlap, hidden-label fields, prior-diagnostic fields, and scorer-internal fields. The scorer reads only captured artifacts and versioned local labels. It must not call a model, fetch a URL, or use the runtime compiler.

## Independent labels and adjudication

Two test experts with distinct nonblank string identities independently and completely label every expert Test Point, generated factual claim, and generated Case. Grounded assertion and Grounded Case IDs are unique within each capture; the capture-scoped output IDs and hidden label keys must close bidirectionally, so omission and duplication cannot raise precision or acceptance or hide an unsupported critical/high Grounded Oracle. Grounded and Blocked Test Point lanes are disjoint subsets of the generated Test Point lane, and Grounded coverage is a subset of Grounded Test Points. Detected defect IDs and killed mutation IDs must belong to the current case's validated evidence. Every coverage signature participates in stability and must have an obligation label. Anchor presence and semantic support are separate fields: a present source locator does not imply that the source supports the claim. Expert identities and complete label sets remain recorded beside the final labels.

Any disagreement requires a completed adjudication with the exact `label_key`, both expert values, resolved value, adjudicator, completion time, and rationale. The final label must equal expert agreement or the completed resolution. Corrections create a new `label_version` with `correction_of`; `prior_versions` retains a gap-free chain of complete prior final labels, expert annotations, and adjudications behind verified SHA-256 digests. Every retained version is validated independently with the same typed label/adjudication rules. A correction may add or remove label keys while preserving the nonempty historical snapshot; it cannot replace history with an empty shell.

## Evaluation-only evidence

Traceable historical defects may be searched and routed as risk evidence, but never override target requirements. Each defect is a dense record with a corpus-unique nonblank ID, a frozen risk, and a nonblank source reference; invalid or duplicate rows do not enter minima or metric denominators. Every explicitly high-risk case includes offline business-model mutations. Mutation kills are reported as a separate enhancement signal and never act as an online truth or release gate.

## Completeness and release boundary

V1 requires all six frozen strata, at least five PRDs per stratum, three critical expert Test Points, two clarification-required PRDs, and five traceable historical defects per stratum. Every PRD requires all twelve captures. Missing labels, runs, disagreements, strata, provenance, or a mandatory nonzero denominator yields `insufficient_evidence`.

Release gates use separate precision, recall, acceptance, defect-recall, and stability metrics with separate confidence intervals. All gated values must be finite unit metrics whose numerator, denominator, and value agree; malformed numeric evidence is `insufficient_evidence`, never a pass. No average may hide an unsupported critical/high Grounded Oracle or a weak domain. The process hard gates are silent formal Test Point loss, fixed-round clarification stop, automatic repeat of unknown/deferred, and recovery of an old revision.
