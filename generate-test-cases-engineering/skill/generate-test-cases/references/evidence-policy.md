# Evidence and source policy

Only accepted authoritative source material and explicit user clarification can establish product truth. Generated Cases, rendered output, execution results, and downstream records can never become sources.

## Source acquisition

Declare every supplied inline text, local path, HTTPS URL, or attachment reference in `source_bootstrap`. The compiler assigns stable Source Request identities, canonical order, and one current batch. Fulfil each requested item with exact material bytes or explicitly mark an optional request `skipped_optional`. Required items cannot be skipped.

Do not persist signed URLs, cookies, bearer values, or expiring access parameters. After retrieval, retain only safe locator metadata, canonical bytes, byte digests, and acquisition audit fields. Preserve source language and technical names.

## Source pack

Write `source_pack` only after acquisition is complete. Use precise locator spans for independently attributable statements. A whole document is not a valid locator for unrelated claims. Preserve conflicts as separate observations; do not silently choose a winner.

## Evidence claims

Each Claim is atomic and binds one exact origin. Separate condition, trigger, action, expected outcome, timing, quantifier, permission, and exception semantics when they are independently reviewable. Use only compiler-issued candidates and review every required candidate exactly once.

Evidence status describes support, not execution readiness. Unsupported or ambiguous truth remains a semantic gap. Do not convert missing truth into a guessed business rule, an execution disposition, or NotApplicable.

Entity resolution must bind the correct conflict group and project every mention into one typed resolution decision. Permission signals retain their role/resource/action/context/dimension coordinates and their exact evidence digests.

## Accepted authority

Accepted `source_pack` and `evidence_claims` bytes are immutable. The compiler seals their envelope, artifact digest, semantic root, provenance edges, and checkpoint in one transaction. Corrections require a newly advertised artifact action or a new run when authoritative bytes or material scope change.
