# Behavior Views

`behavior_views` turns accepted Claims into typed, decidable behavior contracts. It may refine structure but may not invent product truth.

## Required contracts

Review every compiler-issued semantic gap and required-contract seed exactly once. Use stable references from the seed; do not author identities or point at an unregistered semantic rule.

- Field correspondence names the authority side, left/right fields, join, executable transform reference, comparison, null policy, freshness, and basis.
- Value state records distinct absence, null, empty, zero, invalid, and normal axes when relevant. Do not collapse them without explicit evidence.
- Domain contracts define a nonempty partition and its boundary semantics. Complement claims need a finite closed partition or explicit proof.
- Population contracts define the quantified scope and a typed proof. Empty catalogs still require an explicit typed-create contract when creation is in scope.
- Oracle semantic contracts identify the formal test point, observation, assertion, evaluation scope, observation window, and basis.
- Permission matrices cover every compiler-derived coordinate. Each cell resolves Allow, Deny, or Conditional and binds the correct evidence. Deny paths include required denial behavior and data-scope contracts.
- Risk reviews cover every in-scope module and risk kind with a nonempty action rule.

## Clarification boundary

If a required field, domain, population, permission, Oracle, or risk semantic cannot be decided from accepted authority, retain the compiler-issued gap and enter the clarification protocol. Do not place prose placeholders into typed fields.

## Review closure

The artifact is accepted only when candidate coverage is bijective, all references resolve, every typed invariant passes, required auxiliary contracts are reachable from their owning coordinate, and no review row is orphaned. Acceptance produces the behavior semantic root used by Case compilation.
