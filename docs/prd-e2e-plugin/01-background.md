# PRD 驱动 E2E 插件：背景与范围

状态：待实现基线
目标版本：`prd-e2e` 插件 `0.1.0`
适用范围：非生产 B2B Web 系统的 PRD 验收

## 1. 文档用途

本文说明本次建设要解决的问题、已经确定的产品形态、范围边界和成功标准。它不描述具体代码实现；实现方式见 `02-technical-design.md`，可验收要求见 `03-spec.md`。

三份文档共同构成本次实现基线：

1. `01-background.md`：回答“为什么做、做到什么程度”；
2. `02-technical-design.md`：回答“系统如何组成、如何运行”；
3. `03-spec.md`：定义实现必须满足的行为和验收条件。

如实现细节与 Spec 冲突，以 `03-spec.md` 的可验收要求为准；不得以此为由扩展本文定义的范围。

## 2. 当前能力

现有两个 Skill 分别解决不同阶段的问题：

- `generate-test-cases`：把 PRD 等需求材料转换为可追踪的人工功能测试 Case Document；在用户明确要求执行计划时，还可以生成并确认绑定该 Case Document 的 Execution Plan。
- `b2b-e2e-runner`：接收已经确认的 Runner v2 JSON 用例，在非生产 B2B Web 系统中通过 Chrome DevTools MCP 执行，保存账本、证据和可审计 HTML 报告。

两者是独立 Skill。这种独立性是合理的，因为“定义应该验证什么”和“观察系统实际发生了什么”是不同职责。但当前缺少一个稳定的编排层，用户必须手工完成以下工作：

1. 先要求 Agent 使用 `generate-test-cases`；
2. 等待用例生成和必要澄清结束；
3. 再次要求 Agent 使用 `b2b-e2e-runner`；
4. 人工保证两个 Skill 的文件格式、执行范围和上下文能够衔接；
5. 在流程暂停后，人工说明应该恢复哪个阶段和哪个 Run。

## 3. 需要解决的问题

本次建设只解决以下问题：

- 用户只提供 PRD 与测试地址时，Agent 能自动完成用例生成、执行计划确认、格式转换、浏览器执行和结果汇总；
- 子流程需要用户输入时，流程可以暂停，并在用户回答后恢复原 Run；
- 两个子 Skill 使用不同数据契约时，通过确定性转换完成交接，而不是让模型临时改写；
- 用户在一台新电脑上只安装一个插件，即可获得完整能力；
- 插件能够固定并校验三个 Skill 的兼容版本，避免某个 Skill 更新后静默破坏链路。

本次建设不试图合并两个现有 Skill，也不重新实现它们的专业能力。

## 4. 已确定的产品形态

最终交付一个名为 `prd-e2e` 的插件。插件内部包含三个仍然独立的 Skill：

```text
prd-e2e 插件（一个安装单元）
├── run-prd-e2e          新增；负责流程编排和交接
├── generate-test-cases  现有；负责 Case Document 与 Execution Plan
└── b2b-e2e-runner       现有；负责浏览器执行、证据和报告
```

这里有两个必须区分的概念：

- 插件是安装、分发和版本发布单元；
- `run-prd-e2e` 是运行时的流程编排者。

插件本身不执行测试，也不构成第四套业务流程。安装插件后，三个 Skill 仍可分别被发现和使用；当用户提出“根据 PRD 完成 E2E 验收”时，由 `run-prd-e2e` 组织另外两个 Skill。

## 5. 目标用户体验

典型启动请求只需包含：

- 一份或多份属于同一需求范围的 PRD 来源；
- 一个非生产测试地址，或属于同一测试环境的一组地址；
- 可选的测试套件名称。

示例：

> 使用 run-prd-e2e，根据这份 PRD 在这个测试地址完成 E2E 验收。

启动后，用户不需要再手工指定“下一步调用哪个 Skill”。流程仅在必须由用户决定或提供资源时暂停，例如：

- PRD 存在会影响 Case 或预期结果的歧义；
- 需要确认本次实际执行的 Case 列表；
- 测试地址的非生产属性尚未得到明确证明；
- 当前执行批次缺少账号、权限或登录动作；
- 写操作缺少明确的业务清理声明；
- 子 Skill 返回了需要用户处理的可恢复阻塞。

暂停后，用户只回答当前问题。编排 Skill 必须从持久化状态恢复原流程，不能要求用户重新描述前序步骤或再次点名子 Skill。

## 6. 本次范围

### 6.1 包含

- 新建 `run-prd-e2e` 编排 Skill；
- 将 `run-prd-e2e`、`generate-test-cases`、`b2b-e2e-runner` 打包为一个 `prd-e2e` 插件；
- 使用 `generate-test-cases` 生成一个逻辑需求范围的 Case Document；
- 使用 `generate-test-cases` 生成并确认与该 Case Document 绑定的 Execution Plan；
- 将已确认且可执行的 Case 确定性转换为 Runner `schema_version: "2.0"` 输入；
- 在非生产 B2B Web 系统中使用 `b2b-e2e-runner` 执行；
- 保存外层 Run 状态、子 Run 引用、交接产物和最终索引；
- 支持语义澄清、执行确认、账号权限等暂停后的同 Run 恢复；
- 对三个 Skill 做内容摘要锁定、兼容性校验、名称冲突检查和安装冒烟测试；
- 定义子 Skill 更新后的同步、测试、插件版本更新和重新发布流程。

### 6.2 不包含

- 修改 `generate-test-cases` 的业务逻辑或公开契约；
- 修改 `b2b-e2e-runner` 的业务逻辑或公开契约；
- 在 `run-prd-e2e` 中复制或重写两个子 Skill 的内部流程；
- 生产环境测试；
- API 自动化、Playwright 脚本生成或其他浏览器执行器；
- 多项目并发调度、定时执行或后台轮询；
- 自动申请账号、权限或代替用户审批；
- 自动修改 PRD、Case Document 或已经确认的预期结果；
- 根据执行结果反向改写正式 Case；
- 自动删除、覆盖或禁用用户机器上已有的同名 Skill；
- 建设远程 Skill 依赖解析、在线自动更新或插件市场发布系统。

## 7. 核心约束

以下约束在实现中不得被削弱：

1. **职责独立**：编排层不承担用例语义生成，也不承担浏览器事实判定。
2. **语义不可改写**：Case、Step、Oracle ID 以及 Oracle 的预期文本在交接中保持不变。
3. **执行范围明确**：只有经过确认的 Grounded、Execute 且 ready 的 Case 才能交给 Runner。
4. **非生产硬门槛**：不能根据域名习惯猜测环境性质；浏览器执行前必须有明确的非生产证据。
5. **文件是恢复依据**：恢复时读取状态文件和子 Run 权威产物，不根据聊天记忆推断。
6. **Runner 独占执行判断**：正式 Runner Run 开始后，页面动作、证据和四态结果只由 `b2b-e2e-runner` 规则决定。
7. **秘密不落盘**：密码、Cookie、Authorization、Token、Session ID、认证票据、签名值和认证 URL 不得写入状态、日志或报告。
8. **一次安装**：干净环境中安装 `prd-e2e` 插件后，不需要再分别安装三个 Skill。
9. **版本可复现**：发布包内是经过验证的三个 Skill 固定快照，而不是运行时自动读取外部“最新版”。
10. **更新需发新版**：任一内置 Skill 内容变化后，必须重新同步、验证并发布新的插件版本；若子 Skill 契约未变，不要求修改编排逻辑。

## 8. 成功标准

本次实现满足以下条件才算完成：

- 用户一次提供 PRD 和测试地址后，无需手工指定第二个 Skill；
- 必要暂停后能够恢复同一个外层 Run 和对应子 Run；
- Runner 输入只包含已确认、可执行的 Case；
- 交接过程不改写稳定 ID 和预期文本；
- Runner 开始前完成非生产环境、执行范围和业务清理检查；
- 最终结果能够追溯到 Case Document 的不可变引用和摘要；
- 最终对话使用 Runner 生成的四态统计和完整结果表，且链接到唯一的 `report.html`；
- 外层状态和交付物不包含秘密；
- 插件中恰好发现三个预期 Skill，内容与锁文件一致；
- 在无同名冲突的新环境中只安装一次插件，即可发现并使用三个 Skill；
- 更新任一子 Skill 时，验证流程能够检测旧快照，并要求发布新的插件版本。

## 9. 前置依赖

- 可用的 Node.js 22 或更高版本；
- 可写的工作区；
- 可读取的 PRD 来源；
- 当前兼容快照的 `generate-test-cases`；
- 当前兼容快照的 `b2b-e2e-runner`；
- 执行阶段可用的 Chrome 与 Chrome DevTools MCP；
- 用户能够在需要时提供非生产环境证明、账号权限状态及必要登录动作。

这些依赖缺失时，流程应明确报告缺失事实和唯一下一步，不得改用范围外的工具或伪造结果。
