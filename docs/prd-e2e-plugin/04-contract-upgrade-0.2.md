# 0.2.0 契约与源码快照升级

## 背景与授权

2026-09-18 合并门禁真实复现了仓库 Generator 已升级至 `4.3.0 / 0.8.0`、插件仍使用 `4.2.0 / 0.7.0` 的副本漂移。Runner 新提交也需要同步进入插件。用户授权修复插件副本、锁定摘要与兼容接线后继续合并 main。

本文件补充 0.1.0 基线，不回写历史设计或历史 Run。此次只升级打包与契约适配，不改变生成、账号协作、浏览器执行、通过标准、证据或报告业务语义。

## 明确变化

- 插件版本 `0.2.0`；当前发布契约 `Generator 4.3.0 / compiler 0.8.0 / Runner 2.0`。
- 适配器同时接受完整的历史 `4.2.0 / 0.7.0` 交接；同一交接的全部产物必须使用同一版本对，拒绝混用和未知版本。原 ID、步骤顺序、Oracle 文本和范围限制不变。
- 提供严格 Git 源码导出：只从已提交且源目录干净的 HEAD 导出指定子 Skill，记录提交号。拒绝已跟踪依赖、链接和特殊文件；目的目录必须全新，不覆盖已有文件。
- 锁的闭合结构保持 `1.0`，子 Skill 的 `source` 枚举增加 `validated-repository-snapshot`；原安装快照 CLI 默认值仍有效。树摘要算法未放宽，源码快照不包含运行时依赖。
- Runner 依赖按原子 Skill 锁文件在隔离运行副本安装，编排器无新依赖。仓库来源对照、实际 Generator 产物生成到 Runner 输入的兼容测试纳入门禁。

## 验证与限制

需通过插件全部测试、根 Runner 与打包 Runner 全量测试、Generator `check`、Sandbox 回归、Skill/插件结构检查及秘密/路径检查。版本未知、摘要漂移、源目录未提交、混用版本等必须继续失败关闭。

安装到活跃个人 profile 不在本次授权范围内，安装冒烟保持未执行。本地 fixture 的生产函数调用属于接口集成验证，不作为实际用户登录或真实业务测试证据。
