# Runner 执行体验与报告 A：已确认范围

来源：用户在当前任务逐项确认的八项问题、A 阅读版原型及正式开发授权。不是重新设计 Runner。

## 不变边界

只修改仓库版，不覆盖个人安装副本，不提交或推送，不修改历史 Run。不改 schema 2.0、快照、原始 ID/expected、四态聚合、非生产限制、事件账本、秘密保护、副作用防重放、Chrome DevTools MCP 唯一浏览器路径及单 Target CDP Fetch。

## 验收目标

1. 用具体操作说明账号/权限需求，给自然语言回复示例。通用用例复用已确认账号，不虚构“通用配置账号”。准备状态面向用户表达为现在能用、之后准备、本次提供不了；角色/账号/权限组不限定数量和对应关系。无账号且需登录仍须询问。
2. 截图写入被拒时允许工具合法临时输出或真实图片返回值归档；不绕过权限，不伪造截图，不以证据失败改变产品结果。验证真实文件及检查点引用。
3. 上传必须实际选择文件并观察原用例所要求的上传/保存结果。普通图片可创建无敏感内容的真实测试素材；指定内容不得替代。不扫描个人文件，不把输入素材当作截图证据。
4. 缺业务数据时通过授权页面的搜索、筛选、列表、详情及关联记录探索，核实可用条件和原值 ID；沿用每个数据目标最多 10 个不同结果页。不猜 ID、不走隐藏接口、不擅自新建业务数据。
5. 用户独占条件缺失及时协作；工具问题先安全恢复。提供真实尝试和具体行动，继续独立工作，无可做工作再等待并清理本 Run 代理。通知后核验上下文，禁止轮询、催办及副作用重放。
6. 确认、等待、中断只展示简短进度和请求，不自动展示报告/全表。内部阶段产物继续生成。明确测试结束才交付全量结果；用户明确要求阶段结果例外，明确提前结束须标明。
7. 正式 HTML 使用已选 A：分段长耗时、友好 URL、结论优先单栏详情、步骤/预期/实际分层、图片放大、可展开长 ID、短行动摘要连接完整受影响用例。原顺序、分页 20 条、全部事实和安全转义保留，无 B 切换及原型假数据。
8. 未用代理跳过端点检查；需要代理尽量在登录前验证同浏览器和精确 Target。安全自动处理，不让用户寻找端口。涉及重启、登录丢失或其他页面影响先说明和授权。不能连接时不降级为全局代理/monkeypatch、不删除代理前提、不当作产品失败。

真实浏览器验证和隔离自动测试分开列出，不能用后者冒充前者；无法验证的部分如实保留。
